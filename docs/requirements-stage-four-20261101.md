# Requirements Stage 4 — Notifications

Scope: supplier price/RFQ events, durable exception alerts, per-phone registration, and actionable owner notifications. Based on deployed Stage 3 application `4af9fae48b34d588cfdc4f23c266a55c8203b366`.

## Behavior

- Existing stock submission and purchase-order submission/sent alerts remain intact.
- New RFQ sent/declined activity, supplier quotation prices and verified portal final-confirmations notify active administrators. Price header/line changes within one database transaction share one event. Portal draft autosaves are silent. Submitted standing-price versions link to Supplier access for approval.
- A minute database sweep reconciles unresolved supplier responses, insufficient valid quotations, expired quotations, MOQ/order-multiple/MOV overbuy, unapproved costs, late deliveries, rejected goods, invoice variances, unexpected receipt discrepancies, stalled documents, failed/uncertain supplier delivery, and exhausted phone-push retries.
- Each issue includes source reference, responsible role, due date, severity, and a corrective action. Exact RFQ/PO links, receiving follow-up search, invoice-variance filter, and Supplier access are retained. The admin Exceptions / Urgent Work queue and notification bell use the same durable issue records.
- Continuous issues create one event per administrator; source fixes automatically resolve the issue and audit the resolution. Recurrence creates a new episode. Read state does not resolve an outstanding problem. A reasoned four-hour postponement is audited and does not authorize spending, override procurement guards, or falsely resolve an issue. Existing award/receipt override workflows remain the source of business approval/audit.
- No historical price events are replayed. Existing unresolved source problems are discovered by the sweep. Notifications remain limited to active administrators, as requested for the owner's phone; responsible-role labels identify who should perform the corrective work, without giving other roles access to private admin alerts.
- The app refreshes while visible every 20 seconds and on focus. Newly arriving alerts produce a compact in-app toast, without replaying the initial inbox. The inbox and issue queue each display up to 200 recent entries with an explicit limit notice.

## Phone delivery

- Device enablement now checks both browser subscription and the administrator-owned database registration. A test targets this phone only. A successful push-provider response explicitly asks the user to confirm physical display.
- The service-only atomic batch claimant skips already delivered, read, resolved, postponed, expired, and pre-registration history. This fixes the old earliest-200-row starvation bug. Leases last two minutes; attempts increment on claim so crashed workers cannot retry indefinitely. Five attempts, exponential backoff, stable event tags and expired-device cleanup remain. The worker claims ten deliveries per invocation to fit the free Edge Function runtime even when providers are slow.
- Neither public clients nor authenticated staff can claim deliveries. Only the existing service worker credential and service role invoke this capability. Existing RLS remains enabled; client updates remain limited to `read_at`. Postponement checks active admin identity, ownership and current access rules, and requires a reason.
- No paid service, card verification, supplier send flag, approval limit, or category route is changed.

## Acceptance

Automated verification uses isolated production definitions, synthetic users/devices and intercepted browser APIs. No real supplier message, real order, real phone subscription or push-provider delivery is generated by tests.

At start, production had zero phone subscriptions. Physical owner-phone pop-up display must be verified by opening the app on that phone, choosing Notifications → Enable phone notifications → Allow → Send test, and confirming actual display. Server acceptance, automated browser checks and deployment success do not prove Android displayed the notification.
